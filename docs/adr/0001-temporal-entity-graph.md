# 0001 — Temporal Entity Graph

**Контекст**
Для корректного отслеживания состояния системы необходимо хранить историю
жизненного цикла каждой сущности (host, process, cgroup, unit, container,
pod, disk, netif). Требуется, чтобы идентичность оставалась неизменной даже
при пересоздании PID, переименовании cgroup, перезапуске unit и т.д.  Кроме того, надо обеспечивать быстрое сравнение графов (A/B diff) и
генерацию событий (created, deleted, restarted, etc.).

**Решение**
1. Введён тип `EntityKey`, представляющий уникальную и неизменную
   идентичность каждой сущности.  
2. `EntityGraph` хранит текущие сущности в `HashMap<EntityKey, Entity>`.  
3. При каждом такте `EntityGraph` обновляется через `Collector::collect`,
   создавая `EntityRecord` и генерируя `Event` при изменениях.  
4. Внутри графа реализованы строгие инварианты:
   * `EntityId` никогда не переходит на другую сущность – слот арены получает
     новый генерационный номер.  
   * Имена проходят `sanitize_display`.  
   * Перезапуск логической сущности (unit, container, pod) в окне
     `DEFAULT_RESTART_WINDOW_MS` генерирует `Restarted`.  

**Последствия**
- Устойчивый, неизменный идентификатор позволяет без ABA
  корректно сопоставлять события и метрики.  
- Возможность быстрого A/B diff за счёт сохранения `EntityRecord` в истории.  
- Поддержка всех 7 типов сущностей, включая контейнеры и кластеры.  
- Модульность: коллекторы не зависят от логики графа – они только
  передают наблюдения.

**Статус**
Реализовано в `pulse-core::EntityGraph`, `pulse-core::EntityKey`,
`pulse-core::EntityRecord` и `pulse-core::EntityId`. Весь код покрыт
юнит‑тестами, которые проверяют идентичность и инварианты.
