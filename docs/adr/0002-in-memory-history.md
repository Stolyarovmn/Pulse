# 0002 — In‑Memory History

**Контекст**
На типовом хосте Pulse ведёт порядка тысяч серий за такт (замер на стенде WSL2:
около 3 400 серий и 205 сущностей при интервале 1 с). Требуется быстрый доступ к
последним значениям, скорость counter-серий, статистика по окну и история
сущностей и событий для A/B diff. Память при этом обязана иметь потолок, а не
расти вместе со временем работы агента.

**Решение**
1. В `pulse-store` реализована структура `History`, содержащая:
   * `hot: Hot` – кольцо raw‑samples за `hot_ticks` (300 тактов, ~5 мин).  
   * `warm: Warm` – агрегаты за `warm_buckets` (360) бакетов,
     каждый из `warm_bucket_ticks` (10 с). Сохраняются только для
     не‑процессных сущностей.  
   * `entities: Entities` – журнал `EntityRecord` с `max_entity_records`
     (32 768).  
   * `events: Events` – журнал событий с `max_events` (8192).  
2. Методы `ingest(&mut self, batch: &TickBatch)` записывают samples
   в hot, обновляют warm, добавляют `EntityRecord` и `Event` из
   `TickBatch`. При переполнении новых серий, событий или
   записей просто отклоняются и увеличивается счётчик
   `dropped_series`.  
3. Чтения (`latest`, `rate`, `window`, `events_between`) выполняются под
   read-lock `RwLock`; писатель — единственный поток сбора. Отравление замка не
   считается фатальным: структура остаётся согласованной.

**Последствия**
- **Память** ограничена `Store`‑конфигурацией (`max_series`,
  `max_events`, `max_entity_records`); при переполнении старые данные
  удаляются по FIFO.  
- **Производительность** — операции над горячим кольцом и хеш-таблицами
  амортизированно O(1); `window` по тёплому слою линейна по числу бакетов окна.
- **Никакой дисковой персистентности** – при перезапуске агент
  теряет всю историю; это сознательный компромисс ради простоты.  
- **Точность тёплого слоя ограничена.** Суммы квадратов внутри бакета не
  хранятся, поэтому `WindowStats` из тёплого слоя помечается
  `approximate = true`, а потребитель обязан не считать по нему z-оценку.

**Статус**
Полностью реализовано в `pulse-store::History` и тестировано
unit‑тестами. Параметры по умолчанию находятся в `pulse-core::config::Store`.
