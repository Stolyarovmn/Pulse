# Конкурентные критерии Pulse

Документ отвечает на два вопроса: **чем Pulse отличается от уже существующих
инструментов** и **какие его свойства измерены, а какие пока нет**.

Правило документа: каждое число сопровождается командой, которой оно получено,
и стендом, на котором снято. Число без команды считается выдумкой и удаляется.
Сравнительные числа чужих инструментов не приводятся, пока они не сняты на том
же стенде той же методикой: «htop использует 1.5 мс» без замера — такая же
выдумка, как и своя цифра.

## Стенд замеров

| Параметр | Значение |
|---|---|
| Хост | WSL2 Ubuntu 24.04 на Windows 11, ядро `6.18.33.2-microsoft-standard-WSL2` |
| CPU | 12 vCPU (12th Gen Intel Core i7-1255U) |
| RAM | 15.8 ГиБ |
| Наблюдаемых сущностей | 102 |
| Бинарник | `dist/pulse`, статический musl, 3.2 МиБ (`scripts/build-portable.sh`) |
| Дата снятия | 2026-09-20 |

Стенд маленький: 102 сущности и почти праздный хост. Числа ниже верны **для
него** и не переносятся на узел с тысячами процессов без повторного замера.

| 9 | Время первого ответа `pulse top` | `scripts/measure-ttfa.sh 10` | медиана 1247 мс, разброс 218 мс | ≤ 2 интервала | ✅ |

Пояснение к показателю 4. До исправления PULSE-078 замер останавливался перед
записью в историю, и на этом же стенде показывал 28.5 мс вместо 51.4 мс —
стоимость агента занижалась почти вдвое. Числа в таблице сняты уже полной
метрикой: сравнивать их со старыми значениями нельзя.

Пояснение к показателю 9. `pulse top` ждёт **два** такта
(`crates/pulse-cli/src/main.rs:302`): производные величины — доля CPU, скорость
ввода-вывода, темп пакетов — не существуют по одному наблюдению. Поэтому
мгновенного ответа, как у `ps`, здесь быть не может по устройству, и порог
сформулирован в тактах, а не в миллисекундах. Разброс по десяти прогонам —
218 мс, то есть время предсказуемо и определяется интервалом сбора: при
`general.interval_ms = 1000` ответ приходит примерно через 1.2 с.

## Не измерено

Ниже то, о чём заявлять нечего, пока не проведён эксперимент. Раздел существует,
чтобы отсутствие данных не подменялось уверенной формулировкой.

1. Поведение на 10 000 процессов и 50 000 соединений: стенд такого масштаба не
   собирался. Известно только, что обход `/proc` ограничен бюджетом до
   материализации каталога (`PULSE-080`), то есть стоимость такта имеет потолок.
2. Сравнение с htop, btop, glances, Netdata, node_exporter, OTel Collector на
   одном стенде одной методикой: не проводилось. Любые «мы быстрее» до этого
   замера — маркетинг.
3. Поведение на узких терминалах разных эмуляторов (xterm, gnome-terminal,
   screen): есть гейты раскладки в тестах TUI, живой прогон по эмуляторам не
   делался.
4. Стоимость на узле с cgroup-деревом в тысячи узлов и с активной сетью.
5. Потребление при длительной работе (сутки и более): утечки проверялись только
   на коротких окнах и потолком памяти истории.

## Чем Pulse отличается

Сравнение по свойствам, а не по числам. Свойство либо есть, либо нет — это
проверяется чтением документации соседа и запуском.

| Свойство | Pulse | htop/btop/bottom | glances/Netdata/Beszel | node_exporter + Prometheus | witr |
|---|---|---|---|---|---|
| Ставится одним статическим файлом, без root и пакетов | да (3.2 МиБ musl) | пакет или сборка | агент + сервер/веб | агент + сервер | да (один бинарник) |
| Отвечает «кто владелец ресурса» (unit → cgroup → процесс) | да | нет | частично | нет | да, но про запуск |
| Отвечает «почему это запущено» (цепочка предков) | частично (цепочка владения) | дерево процессов | нет | нет | да, это его цель |
| Диагностические правила с доказательством и гистерезисом | да, 8 семейств | нет | пороговые алерты | правила в Prometheus | предупреждения без истории |
| Сравнение двух моментов (A/B diff структуры и метрик) | да | нет | нет | через PromQL и хранилище | нет |
| Локальная история без внешнего хранилища | да, в памяти | нет | да (сервер/БД) | да (сервер) | нет |
| Работает на чужом сервере, где нельзя ничего ставить | да, `scp` одного файла | обычно нет | нет | нет | да |
| Готовые пакеты (apt/brew/winget/AUR) | **нет** | да | да | да | да, 15+ каналов |
| Демонстрация без установки | `--demo` в терминале | нет | публичные демо | публичные демо | браузерная песочница |
| Поддержка не-Linux | нет | да | да | да | да (macOS/Windows/FreeBSD) |

Вывод из таблицы. Отличие Pulse не в «ещё одном красивом top»: рынок TUI-мониторов
переполнен, и написать цветной список процессов сегодня может кто угодно.
Отличие в трёх свойствах, которых у соседей нет одновременно: **владение
ресурсом**, **правила с доказательством** и **сравнение двух моментов** — при
этом без сервера, без агента-демона в кластере и без установки.

Слабое место видно там же: **дистрибуция**. Соседний по духу инструмент
(witr) получил распространение не потому, что делает больше, а потому что его
можно поставить одной строкой в любой системе и попробовать в браузере. У Pulse
переносимый бинарник собирается, но релизов и пакетов нет — попробовать его
невозможно без клонирования репозитория и установки Rust.

## Что делать с разрывами

Порядок по отношению «польза / стоимость»:

1. Релиз с готовым статическим бинарником и контрольными суммами. Без этого
   продукт недоступен любому, кто не собирает Rust.
2. Снять стоимость на большом стенде (тысячи процессов) и опубликовать метод.
3. Сравнительный замер с htop/btop/Netdata одной методикой — только после п. 2.
